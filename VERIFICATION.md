## Isolation review

- **Grouping:** connected components join repeated post IDs and normalized duplicate comments, including transitive connections. Outer splits and training CV folds keep components intact. All rows have one partition. Group construction sees full-corpus post/text identifiers solely to prevent overlap; it never uses labels or fits predictive features.
- **Labels:** labels must be integer IDs 0–3. No ordinal target encoding, label-derived metadata or dataset-wide class-weight computation exists. Logistic regression derives class weights only from the rows passed to each fit. Blank post IDs are rejected explicitly.
- **Preprocessing:** CV clones the entire TF-IDF/classifier pipeline. Candidate fits use training rows; final fit resets the pipeline on training + validation. A regression test verifies that a token appearing only in test comments is absent from the final fitted vocabulary.
- **Selection:** only validation macro-F1 chooses among the three predeclared C values; ties prefer the first/smallest. Training-only CV is diagnostic. Test-label perturbation leaves candidate scores, selected C and predictions unchanged.
- **Test access:** test labels are checked for class coverage and used for final reporting, never fitting or tuning. Such coverage checks are a documented feasibility check, not permission to try multiple seeds. Existing output paths are refused, but a user can still rerun against the same test using a new path; procedural holdout discipline remains necessary.

No residual label/preprocessing/selection leakage was found in this baseline. Historical ensemble code retains its known leakage and is explicitly separated from the supported baseline.

## Generalization and remaining blockers

This is a random **unseen-post, same-population** split augmented with exact normalized duplicate isolation. It does not mirror a competition test distribution automatically and does not establish future-period, unseen-author or deployment performance. Near duplicates, author overlap, time drift and annotation uncertainty remain. Giant duplicate-connected components may make splitting infeasible or distort row/class balance. No uncertainty intervals or fairness/calibration claims are supported.
