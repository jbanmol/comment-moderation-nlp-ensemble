# Reproducible evaluation

`evaluate.py` is the supported clean baseline. V4/V5 scripts and notebooks are historical artifacts with known leakage; their recorded numbers are not comparable to this baseline. Historical scripts require an explicit opt-in to reproduce their known-leaky runs. Their source and notebook outputs remain available for inspection.

## Verified failure

At the source revision `12ccffeb65162a0815f2770b17f93829566f9743`, `v4_solution.py` lines 242–251 aggregate **all training labels** by `post_id` and compute a smoothed mean. Lines 318–324 call that feature engineering before cross-validation starts at line 446. Each validation label therefore contributes to its own encoded feature, the post mean, and the global smoothing prior. V5 duplicates this pattern. Averaging numeric category IDs also imposes an unjustified ordering on nominal labels.

TF-IDF, SVD and scaling are fitted before folds; post aggregates combine labeled and competition test covariates; ensemble weights and class-score offsets are optimized on the same OOF labels used for reporting. Fixing only target encoding would leave the reported scores biased. The replacement starts with a deliberately small text-only model, dropping target encoding and all metadata. Repairing and rerunning the historical ensemble is future work.

## Protocol

1. Require labeled CSV columns `comment`, `post_id`, `label`, with integer classes 0–3 and no missing required values or empty comments. Only use data you are permitted to process.
2. Join rows sharing a post or a case/whitespace-normalized duplicate comment into connected groups. Assign groups using fixed seeds 42/43 to approximately 60% training, 20% validation, 20% test. These are fractions of groups; row fractions can differ. Split construction does not use labels. Reject missing-class splits rather than searching seeds against test outcomes.
3. Fit TF-IDF and class-balanced logistic regression inside each training fold. Report three-fold stratified group CV on the training partition for each predeclared C in `[0.1, 1, 10]`.
4. Select C by validation macro-F1 (ties favor smaller C). Validation is a tuning set; its selected score is not an unbiased benchmark. Refit the selected pipeline on training + validation.
5. Predict the test partition once. Save macro-F1, all four per-class reports, confusion matrix, row-position split assignments, test predictions, dataset SHA-256, provenance, seed, versions and fitted model. Existing output directories are refused.

The test labels are accessed to check class coverage and compute final metrics, never to fit or select a model. Do not tune after inspecting test results. Keep this split frozen; additional iterations need nested evaluation or a new independently sourced holdout. A CLI cannot enforce that procedural commitment across different output paths. The competition's unlabeled `test.csv` is never loaded or used.

## Limits

No claim about performance on real comments, production readiness, fairness, annotation quality, latency, robustness or calibration is supported. Group separation tests generalization to unseen posts, not additional comments on familiar posts. Near duplicates, shared authors (no author field), time drift and semantic overlap can still cross partitions. Group sizes can distort class proportions; large connected components or too few groups can make this protocol infeasible. Macro-F1 alone does not establish business utility. Class definitions in the problem statement and hidden metadata origins still need verification. No confidence intervals or multiple-seed stability study are reported. Validate intended use, annotation quality and minority-class errors before a client deployment.
